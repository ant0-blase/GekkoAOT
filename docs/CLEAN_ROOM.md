# Clean-room and repository content policy

GekkoAOT is intended to remain distributable without bundling copyrighted game or proprietary SDK assets.

## Do not commit

- GameCube ISO/GCM/RVZ/WIA/WBFS/GCZ images;
- extracted game assets or executable binaries from commercial titles;
- Nintendo SDK source code, object files or libraries;
- Nintendo PC emulator/SDK binaries;
- DSP ROM/coef dumps or other firmware unless redistribution rights are explicit;
- proprietary symbol/map files whose redistribution is not permitted;
- near-verbatim generated source reconstructed from proprietary source material;
- source code translated from commercial game executables. Game code is
  compiled ahead of time on the user's machine from the user's own disc and
  never leaves it.

## Allowed project material

- independently written compatibility/runtime code;
- public interface/behavior documentation;
- patches authored for open-source upstream projects under their licenses;
- test descriptions and compatibility results;
- structural metadata derived from executable analysis when it is non-reconstructive and contains no original binary payload;
- hashes, normalized instruction classes, control-flow/data-flow features, call relationships and similar recognition metadata.

## Game code stays on the user's machine

GekkoAOT compiles a game ahead of time on the user's machine, from the
user's own disc. The translated code, generated sources, caches and native
modules are written to local state and never leave that machine: they are not
committed, uploaded or included in releases.

## SDK recognition by fingerprints

To replace SDK functions with native services, the runtime first recognizes
them in the user's executable. Every reference it uses is a non-reversible
fingerprint, never an instruction word:

- `runtime/sdk/sdk_groundtruth_v1.h` stores, per reference function, its
  name, the names of its callees, its stack frame size, counters
  (instruction count, primary-opcode histogram, direct calls, branches,
  returns), a 64-bit hash of its normalized body, 64-bit hashes of its first
  two and three normalized words, and one 8-bit hash per instruction in a
  strict and a relaxed channel. It is generated by
  `tools/sdk_groundtruth_fingerprint.py`.
- Per-instruction hashes are at most 8 bits wide. Wider hashes are
  reversible in practice: with 16 bits per channel, the two channels
  together identify 18.8% of the reference instructions exactly and 81%
  among at most four candidates. A strict match requires both channels to
  agree, which keeps 8-bit hashes as selective as the former words.
- The service corpora (`sdk_service_corpus_v1.h`,
  `debug_corpus_signatures_v33.h`, `native_*_corpus.h`) store a size, two
  64-bit body hashes, a 64-bit prefix hash and counters per function.
- Exact structural proofs (`runtime/sdk/word_proof.h`) store a template of
  mask letters, one per instruction, and the 64-bit hash of the masked
  words. Relocated fields are left out of the hash and checked by code.

The runtime reduces each candidate function of the user's executable the
same way and compares fingerprints. The hash functions are in
`runtime/sdk/structural_signature.h`.

Tests that exercise a recognized SDK body with real instructions read it
from a local directory outside the repository (`GEKKOAOT_SDK_FIXTURES`) and
are skipped without it.

`policy.clean-room` fails if translated game code reappears, if a file of
`runtime/sdk/` holds more than 64 instruction-like 32-bit constants, or if
the per-instruction hashes become wider than 8 bits. A new
recognition technique that needs exact instruction sequences must store
fingerprints instead.

## Firmware replacements

When no IPL ROM is supplied, GekkoAOT serves its own boot-ROM font so games
that call `OSInitFont` can start. The glyphs were drawn for GekkoAOT and
encoded at run time; no data from a Nintendo IPL is included. A user-supplied
IPL always takes precedence, and `GEKKOAOT_ROM_FONT=0` disables the
replacement.

## User-provided material

Users are responsible for supplying their own legally obtained game dumps and any optional firmware/data required by a runtime path. GekkoAOT should reference user files from local state; it should not upload, redistribute or silently copy them into the repository.
